## AI Reflection and Technical Learnings

### 1. Working with the AI Specification Agent
ผมให้ AI อ่านโจทย์ Lab 4 และเอกสาร Lab ก่อนหน้า แล้วแบ่งเป็น Issue ย่อย ก่อนจะร่างเอกสารเสมอ ข้อดีคือเอกสารตรงกับโค้ดจริงของ repo และเรื่องที่โจทย์ไม่ได้ระบุ AI จะเสนอเป็น Decision ให้ผมเลือก แต่ผมต้องคอยตรวจจำนวนและขอบเขต เช่นตอนที่แผนแตกเป็น 10 Issue

### 2. Working with the AI Coding Agent
ผมสั่งให้ถามก่อนเมื่อเจอเรื่องผิดปกติ โดยเฉพาะ migration ซึ่งช่วยกันความเสียหายต่อข้อมูลได้จริง ระหว่างทำ AI เจอเรื่องที่ผมไม่ได้คาดไว้หลายอย่าง เช่น ประวัติ migration ไม่ตรงกับ DB และเทสต์ที่ล้มไม่แน่นอนเพราะ DB ในเครื่อง ผมต้องมีส่วนร่วมในการตัดสินใจ ไม่ใช่รับผลลัพธ์ทั้งหมดตามที่ AI เสนอ

### 3. Prompting and Quality Control Techniques
- ให้เขียนแผนเป็นขั้นตอนต่อ Issue ไว้ก่อน แล้วสั่งสั้นๆ ว่า "ลงมือทำตามแผน"
- สั่งให้หยุดถามเมื่อเจอสิ่งแปลก เช่น migration
- ให้ตรวจงานซ้ำเมื่อสงสัยว่ารอบก่อนทำไม่ละเอียด (เช่นหลังสังเกตว่าตั้งระดับความพยายามของโมเดลต่ำเกินไป)
- ถามกลับเมื่อไม่เข้าใจหรือสงสัยว่ามีบั๊กจริงไหม แทนที่จะรับคำตอบเลย
- ให้ AI แยกว่าอะไรควรแก้ในรอบนี้ อะไรควรเปิด Issue แยก เพื่อให้ 1 branch ต่อ 1 Issue

### 4. What I Verified Myself
- ตรวจหน้า UI ในเบราว์เซอร์เอง และส่งภาพให้ AI ชี้จุดที่ไม่เรียบร้อย
- เลือกเองว่าจะทำ migration แบบ baseline และเลือกเพื่อน reviewer ทุก PR
- ให้เพื่อน review ทุก PR และตอบกลับ comment เอง รวมถึงนำ comment ของเพื่อนมาแก้จริง
- ย้าย Kanban และปิด Issue ด้วยตัวเอง
